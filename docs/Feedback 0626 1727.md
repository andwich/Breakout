## Launch Scene Issues

### `ScreenTransition.busy` not awaited before Victory
In `resolveroundclear`, when transitioning to the victory scene, there's this guard:
```gdscript
if ScreenTransition.busy:
    push_warning("ScreenTransition busy, victory scene not loaded")
else:
    ScreenTransition.change_scene("res://ui/victory.tscn")
```
If `ScreenTransition` is busy (e.g., from the level intro fade), the victory scene **silently fails** — the player just stays on the game screen.  You should either queue the scene change or retry after `await` rather than a fire-and-forget warning.[1]

### Level intro `introgen` guard has an edge case
The `startlevelintro` function correctly uses a generation counter to cancel stale intro timers, but if `loadlevel` is called twice in rapid succession (e.g., during endless mode transitions), the 1-second timer in the first call still holds a reference to the *old* `mygen`.  The `is_instance_valid(self)` check helps, but there's no cancellation of the still-running `SceneTreeTimer` — Godot's `create_timer` returns are not stoppable, so the old timer will always complete and log a no-op but could cause subtle ordering issues. Consider using a member `Timer` node instead for full control.[1]

### Title screen `startgame` skips `RunState.reset()`
`titlescreen.gd → startgame()` sets `RunState.start_level = 1` but never calls `RunState.reset()`.  If `RunState` had a dirty `last_score` from a previous session, the victory screen could display a stale score. The `reset()` method exists — it should be called here.[1]

## Play Mechanism Improvements

### Aim angle resets on re-sticky but doesn't notify
When `disablesticky` fires and the `sticky_release_callback` is not valid (or tree is paused), the stuck ball is force-launched via `launch(Vector2.UP, aim_angle)` — but if the tree *was* paused, this branch silently does nothing (`pass`).  The ball remains stuck on the paddle forever until the player manually inputs. You need to defer the launch to `_process` or fire it on unpause.[1]

### Multiball clones always spawn from `original.position`, not attach offset
In `on_powerup_collected → MULTIBALL`, clones are spawned at `original.position` with `clone.launched = true` and a rotated velocity — but there's no call to `setup_laser_manager` after spawning them.  If a laser power-up is active when multiball triggers, the laser manager only tracks the paddle reference set at `spawnball` time and won't behave correctly with the new clones. This is by design for laser (it fires from the paddle, not balls), but worth documenting explicitly.[1]

### Stuck-escape direction uses `last_velocity` which can be zero
In `ball.gd`, when `stuck_frames >= 30`, the escape direction is derived from `last_velocity.normalized()` with a fallback to a random vector if magnitude is too small.  However the threshold check is `length_squared() < 1.0`, which means a very slow ball (speed ~0.9) would use the random escape even if it had a valid direction. The threshold should probably be `< 0.01` or use `is_zero_approx`.[1]

### `aim_angle` tilt only uses keyboard/mouse delta, not sticky re-aim
When in sticky mode the aim is shown (double-line), but the tilt is derived from `velocity.x / speed * 45°`.  After the ball is caught and the paddle is stationary, `velocity` drops to zero, meaning `aim_angle` snaps to 0° — the player loses any pre-catch tilt information. You could save `aim_angle` before velocity clears and restore it for the sticky idle state.[1]

## Aesthetic Refinements

### Title screen BREAKOUT label has no idle animation
The title screen shows a static "BREAKOUT" label.  Compared to the rest of the game's animated palette (bouncing bricks, pulsing boss glow, confetti), the title feels flat. A simple looping shimmer tween on `modulate` cycling through `NEON_CYAN → NEON_LIME → NEON_MAGENTA` would match the visual language already used elsewhere in `GameTheme`.[1]

### Ball `_draw` inner glow layers use hardcoded white
```gdscript
draw_circle(Vector2.ZERO, 14.0, Color(1.0, 1.0, 1.0, 0.12) * ball_color)
draw_circle(Vector2.ZERO, 10.0, Color(1.0, 1.0, 1.0, 0.25) * ball_color)
draw_circle(Vector2.ZERO, 8.0,  ball_color)
```
The outer glow rings multiply against `ball_color` directly.  For multiball clones with `NEON_MAGENTA` color, the 0.12 alpha outer ring is barely visible and looks like a rendering artifact rather than a glow. Consider using `ball_color.lightened(0.3)` for the outer rings to keep the halo tinted but bright.[1]

### Slow overlay is `Color(0,0,0,0)` — effectively invisible
`slow_overlay` is initialized with black at zero alpha and tweened to `alpha = 0.12`.  Black barely registers on the already-dark `NEON_BG = Color(0.08, 0.05, 0.15)`. For "Slow Balls," a purple tint (matching `NEON_PURPLE = Color(0.6, 0.2, 1.0, 0)`) would be far more readable and matches the power-up's own HUD color already set in `PowerUpRegistry`.[1]

### Score popup uses fixed `offsetleft -8` / `offsetright 8` in HP label
The boss brick HP label in `brick.tscn` has an 8px fixed offset, meaning the label is slightly off-center for multi-digit HP values.  Setting `size_flags_horizontal = SIZE_SHRINK_CENTER` and removing the fixed offset would center it dynamically.[1]

### `play_launch` sound is a basic chirp sweep — consider harmonics
The launch sound is a pure sine sweep from 200–500 Hz over 0.1s.  Adding a quick second harmonic (2× frequency, half amplitude) mixed in using the same `make_chord` pattern already in `AudioManager` would give it more punch without changing the synthesizer architecture.[1]

### FIX 2: `paddle.gd` — sticky timer expiry with paused tree leaves ball stuck forever

**Problem:** `disable_sticky` checks `get_tree().paused` and falls through to `pass` — the ball is permanently stuck.

**Rule:** Store the stuck ball reference; launch it on the next `_process` tick after unpause. Do not launch from `disable_sticky` if the tree is paused.

**File:** `entities/paddle.gd` — add one member variable and modify `disable_sticky` + `_process`:

```gdscript
# ADD at top of var block (near sticky_mode)
var _deferred_launch: bool = false

# REPLACE disable_sticky entirely
func disable_sticky() -> void:
	sticky_mode = false
	sprite.color = Color(0.2, 1.0, 1.0)
	if stuck_ball and is_instance_valid(stuck_ball):
		stuck_ball.global_position = global_position + Vector2(0, -get_ball_attach_offset())
		stuck_ball.velocity = Vector2.ZERO
		stuck_ball.launched = false
	if get_tree().paused or not is_processing() \
			or (sticky_release_callback.is_valid() and not sticky_release_callback.call()):
		_deferred_launch = true   # ← defer instead of pass
	else:
		if stuck_ball and is_instance_valid(stuck_ball):
			stuck_ball.launch(Vector2.UP, aim_angle)
		stuck_ball = null
		_deferred_launch = false

# ADD to _process (not _physics_process — runs even briefly post-unpause)
func _process(_delta: float) -> void:
	if _deferred_launch and not get_tree().paused \
			and (not sticky_release_callback.is_valid() or sticky_release_callback.call()):
		_deferred_launch = false
		if stuck_ball and is_instance_valid(stuck_ball):
			stuck_ball.launch(Vector2.UP, aim_angle)
		stuck_ball = null
	queue_redraw()  # keep aim line live
```

**Test:** Enable Sticky, let 8-second timer expire while paused. Unpause → ball should auto-launch immediately.

### FIX 8: `autoload/audiomanager.gd` — add harmonic to `play_launch`

**Rule:** Mix a second sine at `2× freq` with half amplitude using the existing loop. No new methods needed.

**File:** `autoload/audiomanager.gd` — `play_launch()` inner loop only:

```gdscript
# BEFORE
var freq := 200.0 + t * 3000.0
var sample := sin(2.0 * PI * freq * t) * 0.3 * maxf(0.0, 1.0 - t / 0.1)

# AFTER
var freq := 200.0 + t * 3000.0
var fundamental := sin(2.0 * PI * freq * t)
var harmonic    := sin(2.0 * PI * freq * 2.0 * t) * 0.45  # 2nd harmonic, softer
var sample := (fundamental + harmonic) / 1.45 * 0.3 * maxf(0.0, 1.0 - t / 0.1)
```

The `/1.45` normalizes the mixed signal so peak amplitude stays at `0.3` and avoids clipping into the `clampf` limits.

**Test:** Launch sound has a sharper, punchier attack while staying at same perceived volume.
