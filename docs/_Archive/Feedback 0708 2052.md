## New findings (low severity)

**1. Dead/incomplete feature: laser aim visibility**
`LaserManager._sync_paddle_aim()` calls `_paddle.set_laser_aim_visible(_active)` guarded by `has_method()` — but `Paddle` never defines `set_laser_aim_visible()`, so this is always a no-op. Also `_sync_paddle_aim()` is only called from `set_paddle()`, never from `activate()`/`deactivate()`, and `LaserManager._paddle_aim_visible` is set but never read. This looks like a half-wired feature (distinct laser-aim indicator) rather than a bug — worth either implementing it on `Paddle` or removing the dead plumbing to reduce confusion.

**2. Combo/shake state not reset on level transition (only on full restart)**
`_load_level()` (called on level clear, not just game restart) doesn't touch `_combo_count`, `_combo_timer`, or `_shake_intensity`/`_shake_tween`. Combo carrying across levels is probably intended (nice streak continuity), but if a shake tween is still mid-flight when `_resolve_round_clear()` swaps to the next level, `Main.position` could theoretically be left slightly off `_base_position` until that tween's callback fires. In practice shake durations are short (~0.05–0.08s) against a 1.2s round-clear delay, so this is very unlikely to be visible — just flagging it as the kind of "two systems overlapping" case that's bitten this project before.

**3. Paddle `queue_redraw()` called unconditionally every frame**
In `_process()`, `queue_redraw()` runs regardless of whether sticky pulse, aim lines, or edge warnings actually changed. Not a bug, just a minor inefficiency — could gate it behind `sticky_mode or show_aim or edge_warn > 0` if you want to trim redundant redraws.
