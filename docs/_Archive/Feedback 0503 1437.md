## Opening Scene Bug — Root Cause

**The paddle has no position set in `main.tscn`.** Because the `[node name="Paddle"]` entry has no `position =` property, Godot places it at `(0, 0)` — the top-left corner. Then `spawn_ball` runs:

```gdscript
at = paddle.global_position + Vector2(0, -30)  # → (0, -30), off-screen above viewport
```

The ball spawns 30px above the viewport top. The `VisibleOnScreenNotifier2D` may immediately fire `screen_exited`, though since `y > 720` is false the ball won't self-destruct — it's just invisible. The paddle is also crammed into the top-left corner where it's easy to miss.

**Fix — add to `main.tscn`** under the Paddle node:
```
[node name="Paddle" parent="." instance=ExtResource("2_p4fn3")]
position = Vector2(640, 680)
```

Or set it programmatically at the start of `begin_run()`:
```gdscript
paddle.position = Vector2(get_viewport_rect().size.x / 2.0, get_viewport_rect().size.y - 40.0)
```

## Other Bugs Found

**1. Ball velocity is double-modified on paddle hits (`ball.gd`)**

The aim calculation sets velocity, then `velocity.bounce(normal)` runs on it again:
```gdscript
# aim is calculated and applied here:
var aim := Vector2(hit_ratio * 0.9, -1.0).normalized()
velocity = aim * velocity.length()

# THEN this also runs, mangling the aim calculation:
velocity = velocity.bounce(normal)
```
The bounce call should be skipped when the collider is a Paddle. Fix:
```gdscript
if collider is Paddle:
    # sticky / aim logic ...
else:
    velocity = velocity.bounce(normal)
```

**2. Endless mode loops to victory screen (`main.gd` line ~120)**

```gdscript
if current_level >= 5:   # ← bug: wave 6, 7, 8... all hit this
```
Should be `== 5`. Endless starts at level 6, so `>= 5` sends every completed endless wave back to the victory screen.

**3. `_reset_round_nodes` doesn't clear balls between levels**

When moving from level 1 → 2, balls from the previous round are still live and bouncing. Only bricks and powerups are cleared. Add:
```gdscript
func _reset_round_nodes() -> void:
    for child in balls_container.get_children():
        child.queue_free()
    for child in bricks_container.get_children():
        child.queue_free()
    for child in powerups_container.get_children():
        child.queue_free()
```

**4. `hud.show_game_over` has an `await` with a 1.5s delay**

The 1.5-second delay before the game-over text appears means if the player presses Space quickly (which is valid, since `phase == GAME_OVER` immediately), `restart()` fires while the async function is still running mid-await — potentially causing a race. Remove the `await` or show the label immediately and delay only the score text update.

**5. `LaserBeam` fires into collision mask 5 (brick layer), but `brick.tscn` uses `collision_layer = 4` (also the brick layer)**

Actually this one is fine — in Godot's bitmask encoding, layer 3 = value 4, so `collision_layer = 4` is indeed the brick layer. The project.godot confirms this. No bug here, just confusing notation.

## State model

Right now `main.gd` decides what Space does by checking things like `hud.gameoverlabel.visible`, pause state, and whether any ball has `launched == false`, which means UI state is doubling as gameplay state.  A cleaner design is to introduce a `GameState` enum such as `READY`, `PLAYING`, `PAUSED`, `GAME_OVER`, and `VICTORY`, then let `_unhandled_input(event)` switch behavior off that single state value instead of multiple scattered conditions.  That would also make the launch prompt, pause label, and restart flow easier to reason about because `HUD` would only render state, not define it.[1]

A concrete pattern would be: when `_ready()` finishes, set `state = READY`; when the player launches any waiting ball, set `state = PLAYING`; when all launched balls are lost and lives remain, return to `READY`; when lives hit zero, switch to `GAME_OVER`; and when level 5 ends, switch to `VICTORY` before changing scenes.  That removes hidden coupling like “game over means a certain label is visible,” which is brittle and easy to break during HUD changes.[1]

### `game/level_defs.gd`

```gdscript
class_name LevelDefs
extends RefCounted

static func base_levels() -> Array[Dictionary]:
    return [
        {"cols": 8, "rows": 4, "speedmult": 1.0, "bosshp": 0, "metalhp": 0, "dropchance": 0.15},
        {"cols": 10, "rows": 5, "speedmult": 1.1, "bosshp": 0, "metalhp": 2, "dropchance": 0.20},
        {"cols": 10, "rows": 6, "speedmult": 1.2, "bosshp": 3, "metalhp": 3, "dropchance": 0.25},
        {"cols": 12, "rows": 6, "speedmult": 1.3, "bosshp": 5, "metalhp": 0, "dropchance": 0.27},
        {"cols": 12, "rows": 7, "speedmult": 1.45, "bosshp": 5, "metalhp": 3, "dropchance": 0.30}
    ]

static func config_for_level(level: int) -> Dictionary:
    var defs := base_levels()
    if level <= defs.size():
        return defs[level - 1].duplicate()

    var wave := level - defs.size()
    return {
        "cols": mini(14, 10 + wave),
        "rows": mini(10, 5 + wave / 2),
        "speedmult": 1.0 + wave * 0.15,
        "bosshp": 0 if wave < 2 else mini(8, 3 + wave),
        "metalhp": 0 if wave < 1 else mini(5, 2 + wave / 2),
        "dropchance": 0.25 + wave * 0.02
    }
```

### `game/level_builder.gd`

```gdscript
class_name LevelBuilder
extends RefCounted

const BRICK_W := 60
const BRICK_H := 24
const BRICK_PAD := 4
const START_Y := 40.0

func build_level(container: Node, brick_scene: PackedScene, viewport_size: Vector2, config: Dictionary, on_destroyed: Callable) -> int:
    var cols: int = config["cols"]
    var rows: int = config["rows"]
    var total_w := float(cols * (BRICK_W + BRICK_PAD) - BRICK_PAD)
    var start_x := (viewport_size.x - total_w) / 2.0
    var count := 0

    for row in range(rows):
        for col in range(cols):
            var brick := brick_scene.instantiate() as Brick
            brick.position = Vector2(start_x + col * (BRICK_W + BRICK_PAD), START_Y + row * (BRICK_H + BRICK_PAD))
            configure_brick(brick, row, col, rows, config)
            brick.destroyed.connect(on_destroyed)
            container.add_child(brick)
            count += 1

    return count

func configure_brick(brick: Brick, row: int, col: int, total_rows: int, config: Dictionary) -> void:
    var hp := 1
    var drop := float(config.get("dropchance", 0.25))
    var is_boss := false
    var brick_type := "standard"

    if config.get("bosshp", 0) > 0 and row == 0 and col == 3:
        hp = config["bosshp"]
        drop = minf(0.6, drop + 0.2)
        is_boss = true
        brick_type = "boss"
    elif config.get("metalhp", 0) > 0 and row == 1:
        hp = config["metalhp"]
        drop = minf(0.6, drop + 0.1)
        brick_type = "metal"

    brick.max_hp = hp
    brick.point_value = (total_rows - row) * 10 * hp
    brick.is_boss = is_boss
    brick.brick_type = brick_type
    brick.drop_chance = drop
```

```gdscript
class_name LevelDefs
extends RefCounted

static func base_levels() -> Array[Dictionary]:
    return [
        {"cols": 8, "rows": 4, "speedmult": 1.0, "bosshp": 0, "metalhp": 0, "dropchance": 0.15},
        {"cols": 10, "rows": 5, "speedmult": 1.1, "bosshp": 0, "metalhp": 2, "dropchance": 0.20},
        {"cols": 10, "rows": 6, "speedmult": 1.2, "bosshp": 3, "metalhp": 3, "dropchance": 0.25},
        {"cols": 12, "rows": 6, "speedmult": 1.3, "bosshp": 5, "metalhp": 0, "dropchance": 0.27},
        {"cols": 12, "rows": 7, "speedmult": 1.45, "bosshp": 5, "metalhp": 3, "dropchance": 0.30}
    ]

static func config_for_level(level: int) -> Dictionary:
    var defs := base_levels()
    if level <= defs.size():
        return defs[level - 1].duplicate()

    var wave := level - defs.size()
    return {
        "cols": mini(14, 10 + wave),
        "rows": mini(10, 5 + wave / 2),
        "speedmult": 1.0 + wave * 0.15,
        "bosshp": 0 if wave < 2 else mini(8, 3 + wave),
        "metalhp": 0 if wave < 1 else mini(5, 2 + wave / 2),
        "dropchance": 0.25 + wave * 0.02
    }
```

### `game/level_builder.gd`

```gdscript
class_name LevelBuilder
extends RefCounted

const BRICK_W := 60
const BRICK_H := 24
const BRICK_PAD := 4
const START_Y := 40.0

func build_level(container: Node, brick_scene: PackedScene, viewport_size: Vector2, config: Dictionary, on_destroyed: Callable) -> int:
    var cols: int = config["cols"]
    var rows: int = config["rows"]
    var total_w := float(cols * (BRICK_W + BRICK_PAD) - BRICK_PAD)
    var start_x := (viewport_size.x - total_w) / 2.0
    var count := 0

    for row in range(rows):
        for col in range(cols):
            var brick := brick_scene.instantiate() as Brick
            brick.position = Vector2(start_x + col * (BRICK_W + BRICK_PAD), START_Y + row * (BRICK_H + BRICK_PAD))
            configure_brick(brick, row, col, rows, config)
            brick.destroyed.connect(on_destroyed)
            container.add_child(brick)
            count += 1

    return count

func configure_brick(brick: Brick, row: int, col: int, total_rows: int, config: Dictionary) -> void:
    var hp := 1
    var drop := float(config.get("dropchance", 0.25))
    var is_boss := false
    var brick_type := "standard"

    if config.get("bosshp", 0) > 0 and row == 0 and col == 3:
        hp = config["bosshp"]
        drop = minf(0.6, drop + 0.2)
        is_boss = true
        brick_type = "boss"
    elif config.get("metalhp", 0) > 0 and row == 1:
        hp = config["metalhp"]
        drop = minf(0.6, drop + 0.1)
        brick_type = "metal"

    brick.max_hp = hp
    brick.point_value = (total_rows - row) * 10 * hp
    brick.is_boss = is_boss
    brick.brick_type = brick_type
    brick.drop_chance = drop
```

Make the HUD state-oriented, not label-oriented.  Your current HUD already has nice methods like `update_score`, `update_lives`, `update_level`, `show_launch_prompt`, `show_pause`, and `show_game_over`, but `main.gd` still depends on a specific node like `hud.gameoverlabel.visible` for logic.[1]

Refine `ui/hud.gd` into something like:

```gdscript
class_name HUD
extends CanvasLayer

func sync(score_value: int, lives_value: int, level_value: int, high_score_value: int) -> void:
    update_score(score_value)
    update_lives(lives_value)
    update_level(level_value)
    update_high_score(high_score_value)
```

```gdscript
func show_ready(show: bool) -> void:
    launch_prompt.visible = show
```

```gdscript
func show_game_over(show: bool, final_score: int = 0) -> void:
    game_over_label.visible = show
    if not show:
        return

    var high := SaveData.get_high_score()
    if high > 0:
        game_over_label.text = "GAME OVER\n%d\nHigh Score %d\nSPACE to Restart" % [final_score, high]
    else:
        game_over_label.text = "GAME OVER\n%d\nSPACE to Restart" % final_score
```

The key design rule is: `HUD` should expose stateful methods, but `Main` should never inspect HUD internals to infer game rules.[1]

## Step 9

Fix `ui/victory.gd` the same way and keep endless-mode transition explicit.  Your current script sets `Colors.startlevel = 6` and changes back to `main.tscn`, but the input callback is again `inputevent`, which means the start action is likely broken there too.[1]

Use:

```gdscript
func _unhandled_input(event: InputEvent) -> void:
    if event.is_action_pressed("ui_accept") or event.is_action_pressed("click"):
        start_endless()
```

```gdscript
func start_endless() -> void:
    RunState.start_level = 6
    get_tree().change_scene_to_file("res://main.tscn")
```

And in `_ready()`:

```gdscript
func _ready() -> void:
    title_label.text = "YOU WIN!"
    score_label.text = "Score %d" % RunState.last_score
    SaveData.save_high_score(RunState.last_score)

    var high := SaveData.get_high_score()
    high_score_label.visible = high > 0
    if high > 0:
        high_score_label.text = "High Score %d" % high

    prompt_label.text = "All 5 levels cleared! SPACE or CLICK for Endless Mode"
```

That keeps the scene handoff simple and makes the endless-run entry point obvious.[1]

## Migration order

Here’s the order I’d actually do it in, to avoid breaking too much at once:

1. Rename `inputevent` to `_unhandled_input` in `main.gd` and `ui/victory.gd`.[1]
2. Add `GameState.Phase` and use it for launch/pause/restart routing.[1]
3. Split `Colors` into `Theme`, `RunState`, and `SaveData`.[1]
4. Extract `LevelDefs` and `LevelBuilder` from `main.gd`.[1]
5. Clean up `Paddle` timers and ball/paddle attachment API.[1]
6. Refine `HUD` so it renders state but never defines game logic.[1]
