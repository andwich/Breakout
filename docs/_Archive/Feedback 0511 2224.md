## 🔴 Critical / Functional Issues

### 1. Ball collision mask doesn't include walls
In `ball.tscn`, the ball's `collision_mask = 37` (binary: `100101`) — layers 1 (paddle), 3 (brick), 6 (wall). But walls in `main.tscn` are on `collision_layer = 32` (layer 6). This actually works, but it's fragile — **laser beams have `collision_mask = 4` (layer 3 only)** and will pass through the top wall silently, which is correct by design but worth documenting. More importantly: the ball can exit through the side walls if the wall StaticBodies aren't sized to cover the full 720px height. The wall shapes are `Vector2(20, 720)` centered at y=360 — this is fine, but if the window ever resizes, walls don't reposition. There's no `size_changed` handler on walls unlike `PlayfieldBorder`.

### 2. `_resolve_round_clear` is reachable when `_transitioning` is set but phase hasn't changed yet
The `_on_brick_destroyed` callback fires on signal, and multiple bricks can be destroyed in the same physics frame (laser + ball hitting simultaneously). The `_transitioning` guard prevents double-entry, but `brick_count` can go negative on the same frame before the guard sets. The `max(0, brick_count - 1)` clamp handles this — however if `brick_count` hits 0 twice before `_transitioning = true` is processed, `_resolve_round_clear` is called twice. You need to move the `_transitioning` check into `_on_brick_destroyed` before the `brick_count` decrement:

```gdscript
func _on_brick_destroyed(pos: Vector2, drop_chance: float) -> void:
    if _transitioning:
        return
    brick_count = max(0, brick_count - 1)
    _spawn_powerup(pos, drop_chance)
    if brick_count <= 0:
        _resolve_round_clear()
```

This is already the case — good — but `_resolve_round_clear` also checks `phase != PLAYING`, so there's a secondary guard. Still, `_life_lost_pending` doesn't protect this path.

### 3. `_on_ball_lost` guard missing `PAUSED`
```gdscript
if phase in [GameState.Phase.GAME_OVER, GameState.Phase.ROUND_CLEAR, GameState.Phase.LEVEL_INTRO, GameState.Phase.READY, GameState.Phase.VICTORY, GameState.Phase.TITLE]:
```
`PAUSED` is not in this list. If the ball falls off screen while paused (e.g. `get_tree().paused` doesn't stop `VisibleOnScreenNotifier2D` signals), a life is deducted. Add `GameState.Phase.PAUSED` to the guard.

### 4. `_spawn_ball` uses `_NO_POS` sentinel but `Vector2 == Vector2` comparison is unreliable for floats
```gdscript
if at == _NO_POS:
```
GDScript uses exact equality for Vector2 comparisons, so this technically works since `_NO_POS` is a constant. But a cleaner and more idiomatic approach:

```gdscript
func _spawn_ball(at: Vector2 = Vector2(-99999.0, -99999.0)) -> Ball:
    var spawn_pos := at if at.x > -9999.0 else paddle.global_position + Vector2(0, -30)
```

Or simply use a nullable approach with an optional parameter flag. Minor but worth noting.

### 5. Victory triggers at `current_level >= BASE_LEVEL_COUNT` — but `_resolve_round_clear` loads `current_level + 1` before the check
```gdscript
if current_level >= BASE_LEVEL_COUNT:
    # victory
    return
_load_level(current_level + 1)
```
This is correct — you check *before* loading the next level. No bug here, just confirm this is intentional (beating level 5 triggers victory, endless starts from level 6 via `RunState.start_level`). ✅

## 🟡 Gameplay / Design Issues

### 6. Multiball clones inherit `_slow_timer` state incorrectly
In `_spawn_ball`, new balls get slowed speed if `_slow_timer` is running:
```gdscript
if not _slow_timer.is_stopped():
    _original_ball_speeds[ball.get_instance_id()] = ball.speed
    ball.speed = ball.speed * 0.6
```
But multiball clones set `clone.launched = true` *after* `_spawn_ball`, bypassing the `attach_to_paddle` path. The slow is applied correctly. However: when `_restore_ball_speeds` fires, it only restores balls currently in `balls_container`. If a clone was `queue_free()`d during the slow period, its instance ID remains in `_original_ball_speeds` causing a harmless but growing dict. Add a cleanup step:

```gdscript
func _restore_ball_speeds() -> void:
    for b in balls_container.get_children():
        if b is Ball and _original_ball_speeds.has(b.get_instance_id()):
            b.speed = _original_ball_speeds[b.get_instance_id()]
    _original_ball_speeds.clear()  # already there ✅
```
Actually this is already handled by `.clear()` — ✅. The dict grows during the slow period only. Fine.

### 7. Aim indicator shows during ROUND_CLEAR if ball is still alive
`paddle.show_aim` is only cleared in `_launch_waiting_ball()` and `paddle.reset()`. If a ball falls while `ROUND_CLEAR` is in progress (edge case: last brick destroyed, ball still bouncing, then falls) — `show_aim` stays true on the paddle even after the transition. Not critical since the round clears, but visually inconsistent.

### 8. Powerup fall speed is constant regardless of ball speed scaling
Endless mode scales ball speed up to 2.5×, but powerup fall speed stays at 120.0. At high waves this creates a disconnect — powerups feel very slow relative to the frantic pace. Consider:
```gdscript
# In _spawn_powerup or powerup.gd
p.fall_speed = 120.0 + (current_level - 5) * 10.0  # subtle escalation
```

### 9. Laser beams don't check for `ROUND_CLEAR` phase
If laser fires right as the last brick is destroyed, a beam can travel upward through an empty field and then hit a brick spawned by the *next* level that loads while the beam is still alive. The laser is deactivated at the start of `_load_level`, but in-flight beams persist. Add:
```gdscript
# In _load_level, after laser_manager.deactivate():
for child in laser_manager.get_children():
    if child is LaserBeam:
        child.queue_free()
```

### 10. Sticky paddle can catch a ball during `LEVEL_INTRO` 
If a ball somehow exists during intro (edge case: signal delayed from prior frame), `stick_ball` can set `stuck_ball` before `paddle.reset()` is called in `_load_level`. The reset clears it, but the sequence could race. Not practically reachable but defensive coding would help.

## 🟢 Aesthetic / Polish Issues

### 11. Ball glow uses `_draw()` but no `queue_redraw()` on speed change
The ball's visual never changes based on speed, so this is fine as-is. But if you ever want the glow to pulse or react to speed, you'd need `queue_redraw()`. Currently the glow layers are static (correct).

### 12. `PlayfieldBorder` draws at z=0 — may render behind background
`BackgroundOverlay` is a `ColorRect` child of `Main` (Node2D). `PlayfieldBorder` is also a Node2D child. Their draw order depends on scene tree order — `BackgroundOverlay` comes first in `main.tscn`, so `PlayfieldBorder` renders on top. ✅ No issue, just worth being intentional about.

### 13. Level intro panel has fixed pixel offsets but no min-size
```
offset_left = -220.0
offset_right = 220.0
```
At 1280×720 this centers fine. But the panel doesn't use `custom_minimum_size`, so if the level name is long ("ENDLESS WAVE 12  ·  SURVIVE THE ESCALATION") it could overflow. Add `custom_minimum_size = Vector2(440, 100)` to the panel, or enable `autowrap_mode` on `LevelIntroTitle`.

### 14. `HUD.update_level()` hardcodes `<= 5` instead of `BASE_LEVEL_COUNT`
```gdscript
func update_level(new_level: int) -> void:
    if new_level <= 5:   # should be BASE_LEVEL_COUNT
```
`BASE_LEVEL_COUNT` is defined in `main.gd` but not accessible from `hud.gd`. Either pass it as a parameter, expose it as an autoload constant, or use `LevelDefs.base_levels().size()`. Currently it's a magic number.

### 15. Power-up icon label uses fixed font size 12 — may be hard to read
The `SymbolLabel` in `powerup.tscn` uses `font_size = 12`. The powerup sprite is 20×20px, so the icon is quite small. Bumping to `font_size = 14` or `16` with the label using full extent would improve legibility, especially for "↓" and "♥" which render small.

### 16. `GameOverLabel` and `PauseLabel` use fixed offsets (440–840px range)
These are centered for 1280px wide but use fixed offsets rather than anchors. If the viewport ever changes size, these drift. Use `anchor_left = 0.5`, `anchor_right = 0.5` with `grow_horizontal = 2` like `LevelCompleteLabel` does.

### 17. Boss brick glow color is hardcoded red in `brick.gd` and not driven by `row_color`
```gdscript
_shader_mat.set_shader_parameter("glow_color", Color(1.0, 0.2, 0.2, 1.0))
```
This is intentional for boss bricks. But it means the boss brick `row_color` export is ignored visually. Either remove `row_color` from boss bricks in `level_builder`, or use `row_color` as the glow color for variety in endless mode.

## 🔵 Code Quality / Architecture

### 18. `PowerUpRegistry` is a `RefCounted` with only `static` methods — should be a plain `class` or namespace
Using `extends RefCounted` with all-static methods means it can never be instantiated usefully and doesn't benefit from RefCounted's memory management. Consider `extends Object` or just using it as a static class (GDScript 4 supports `class_name Foo` with all statics fine with `extends Object`). Minor.

### 19. `_has_active_ball()` and `_get_waiting_ball()` both iterate `balls_container` separately — could be one pass
Not a perf concern at this scale, but a combined helper would be cleaner:
```gdscript
func _ball_status() -> Dictionary:
    var result := {"waiting": null, "active_count": 0}
    for child in balls_container.get_children():
        if child is Ball:
            if child.launched: result["active_count"] += 1
            elif result["waiting"] == null: result["waiting"] = child
    return result
```

### 20. `main.tscn` wall sizes are hardcoded to 1280×720
`RectangleShape2D_sidewall` is `Vector2(20, 720)` and the walls are positioned for 1280px wide. There's no dynamic resizing. Since `project.godot` sets a fixed viewport this is fine, but the `PlayfieldBorder` resizes while walls don't — this could look inconsistent if stretch mode is ever enabled.
