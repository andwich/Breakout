## Bugs

**1. Life lost during `ROUND_CLEAR`**

In `_on_ball_lost()`, the only guard against life deduction is checking `GameState.Phase.GAME_OVER`. But during the 1.2-second `ROUND_CLEAR` pause, balls are still live — if the last ball drifts off the bottom in that window, `_has_active_ball()` returns false (no launched balls left), lives are deducted, and the game enters an inconsistent state where both the level-complete transition and a life-loss reset are in flight simultaneously.

```gdscript
# _on_ball_lost() — add ROUND_CLEAR guard
func _on_ball_lost() -> void:
    if phase in [GameState.Phase.GAME_OVER, GameState.Phase.ROUND_CLEAR]:
        return
    ...
```

**2. `ShaderMaterial` recreated on every `take_damage()` call**

In `brick.gd::_update_visual()`, both the boss and metal branches do `var mat := ShaderMaterial.new()` unconditionally. On a metal brick with 3 HP, three new shader material objects are allocated over the brick's lifetime, and on a busy level with lots of laser fire, this compounds. Cache the material in `_ready()` instead:

```gdscript
var _shader_mat: ShaderMaterial   # field

func _ready():
    _hp = max_hp
    # build material once
    match brick_type:
        "metal":
            _shader_mat = ShaderMaterial.new()
            _shader_mat.shader = SCAN_SHADER
            _shader_mat.set_shader_parameter("frequency", 40.0)
            _shader_mat.set_shader_parameter("intensity", 0.15)
            _sprite.material = _shader_mat
        "boss":
            _shader_mat = ShaderMaterial.new()
            _shader_mat.shader = GLOW_SHADER
            _shader_mat.set_shader_parameter("glow_intensity", 2.0)
            _shader_mat.set_shader_parameter("glow_color", Color(1.0, 0.2, 0.2, 1.0))
            _sprite.material = _shader_mat
    _update_visual()
```

Then `_update_visual()` only updates the alpha for standard bricks and leaves the shader bricks alone.

**3. Authored level name never shown in the intro panel**

`_level_title_text()` returns `"LEVEL %d"` always. The whole authored-name system (`"Opening Volley"`, `"Metal Core"`, etc.) is invisible to the player — it only lives in the dictionary. The intro panel title should display the authored name, with the level number in the subtitle:

```gdscript
func _level_title_text() -> String:
    var config := LevelDefs.config_for_level(current_level)
    var authored := str(config.get("name", ""))
    if authored.is_empty():
        return "LEVEL %d" % current_level
    return authored.to_upper()

func _level_subtitle_text() -> String:
    var config := LevelDefs.config_for_level(current_level)
    var teaching := str(config.get("intro_text", ""))
    var prefix := "LEVEL %d  —  " % current_level if current_level <= 5 \
        else "WAVE %d  —  " % (current_level - 5)
    return prefix + teaching
```

## Significant

**4. Vestigial `GameState.Phase.TITLE` assignment in `_start_new_run()`**

`_start_new_run()` sets `phase = GameState.Phase.TITLE`, then calls `_load_level()` → `_start_level_intro()` which immediately sets `phase = GameState.Phase.LEVEL_INTRO`. The TITLE assignment is never visible. The TITLE phase in `main.gd`'s context is a dead state — the actual title screen is its own scene. This is a minor correctness issue but will confuse anyone reading the phase flow. Remove the assignment or comment that it's intentional no-op.

**5. Audio system is fully wired but entirely silent**

`ScoreSfx` is an `AudioStreamPlayer` in the scene tree, `_on_brick_hit()` checks `score_sfx.stream` before calling `.play()`, and the check is correct — but no stream is ever assigned in `main.tscn`. The conditional guard means it silently does nothing rather than erroring. This is actually fine as a placeholder, but worth noting that the sound system is completely non-functional and players get no audio feedback at all. Even a short procedurally-generated beep via `AudioStreamGenerator` would significantly improve game feel.

**6. Aim indicator draws during non-aim phases**

`paddle.gd::_draw()` draws the aim V-lines whenever `draw_aim` is true, which is whenever `stuck_ball` is absent or invalid. This means the aim indicator is visible during `ROUND_CLEAR` (when the level complete banner is shown) and briefly during `LEVEL_INTRO`. The paddle should only draw the aim indicator when the HUD `launch_prompt` is visible — i.e., during `READY` phase. The cleanest fix is to expose a flag on Paddle:

```gdscript
var show_aim := false  # set to true in _begin_ready_phase, false otherwise

func _draw() -> void:
    var draw_aim := show_aim and (
        (stuck_ball and is_instance_valid(stuck_ball) and sticky_mode) or not stuck_ball
    )
```

**7. Power-up drop chance not capped relative to HP remaining**

Bricks that take damage but haven't been destroyed (metal bricks at 2/3 HP) can still drop power-ups — `_on_brick_destroyed` is only called on `destroy()`, so that path is fine. However, level 5's `drop_chance` of 0.28 combined with boss bricks getting `minf(0.6, 0.28 + 0.2) = 0.48` means nearly half of boss brick destructions spawn a power-up. On a level with multiple boss bricks, the field can fill with power-ups. Consider a soft cap or a global cooldown (e.g., 2-second lockout after any drop) to keep the drop cadence feeling special rather than routine.

## Aesthetic

**8. Ball has no glow — flat against the neon palette**

The neon shaders on bricks, the cyan paddle, and the magenta power-ups all have glow or scanline effects. The ball is a plain flat `draw_circle(Vector2.ZERO, 8.0, Color(1.0, 1.0, 0.6))` with no corresponding effect. Adding a soft halo via two concentric circles in `_draw()` makes it feel native to the palette:

```gdscript
func _draw() -> void:
    draw_circle(Vector2.ZERO, 14.0, Color(1.0, 1.0, 0.6, 0.12))  # outer halo
    draw_circle(Vector2.ZERO, 10.0, Color(1.0, 1.0, 0.6, 0.25))  # inner halo
    draw_circle(Vector2.ZERO, 8.0,  Color(1.0, 1.0, 0.6))        # core
```

**9. Brick destruction particles always golden, ignoring row color**

In `level_builder.gd::_configure_brick()`, the particle `mat.color` is set correctly per-row — but only for the GPUParticles2D `process_material`. The `Particles` node in `brick.tscn` has its own `ParticleProcessMaterial` defined in the scene with `color = Color(1.0, 0.8, 0.0, 1.0)` hardcoded. Since you `mat.duplicate()` correctly, the override does apply — but `_update_visual()` in `brick.gd` doesn't reapply when the brick changes color state (e.g., modulate.a changes on damage). The particles also fire on damage (not just destroy), so on a metal brick the damage burst is always golden rather than matching the brick. Pass the row color to the brick as an exported property and apply it to both the sprite modulate and particle material in one place.

**10. Power-ups don't animate while falling**

The `_physics_process` in `powerup.gd` just translates Y. A slow rotation or pulse on the `modulate.a` would make them feel much more collectible. A simple tween in `_ready()`:

```gdscript
func _ready():
    body_entered.connect(_on_body_entered)
    _update_visual()
    var t := create_tween().set_loops()
    t.tween_property(self, "modulate:a", 0.6, 0.35)
    t.tween_property(self, "modulate:a", 1.0, 0.35)
```

**11. `RunState.reset()` called twice before game starts**

In `title_screen.gd`, `_ready()` calls `RunState.reset()` and `_start_game()` also calls it. Since the title screen is the entry scene and `_ready()` runs unconditionally, the second reset in `_start_game()` is redundant. Remove it from `_ready()` — the reset on start is the correct place to ensure clean state.

**12. `PlayfieldBorder` never redraws on resize**

`playfield_border.gd::_draw()` references `get_viewport_rect().size` but never calls `queue_redraw()` when the window resizes. For a fixed 1280×720 project this is harmless, but if window resizing is ever enabled it silently renders a stale border. Add `get_viewport().size_changed.connect(queue_redraw)` in `_ready()` as defensive practice.
