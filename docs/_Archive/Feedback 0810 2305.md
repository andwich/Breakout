The launch-scene loop is caused by a malformed **`res://entities/ball.tscn`**, not by the title screen. When Start calls `ScreenTransition.change_scene("res://main.tscn")`, Godot fails to parse `main.tscn` because `main.gd` preloads `ball.tscn`; the scene-switch then fails and you remain on the title scene. The debugger specifically reports `Parse Error: Unknown tag "sub_resource"` for `res://main.tscn`, which is the downstream symptom of this broken dependency.[1]

## Root cause

Godot `.tscn` files require all `[sub_resource ...]` blocks to appear **before every `[node ...]` block**. Your project documentation identifies that `entities/ball.tscn` has a trail-material subresource declared after node definitions—an invalid order that prevents the ball scene from loading, which in turn makes the typed preload in `main.gd` fail.[1]

The non-fatal warnings shown above the red errors—unused variables and `CanvasLayer.show` parameter shadowing—do not explain the failed scene transition. The red parser errors do.[1]

## Fix `entities/ball.tscn`

Open `res://entities/ball.tscn` and move the **entire** late `[sub_resource ...]` definition for the ball-trail material to the resource section at the top, immediately after the `[gd_scene ...]` header and alongside any other `ext_resource`/`sub_resource` declarations.

The desired structure is:

```ini
[gd_scene load_steps=..., format=3]

[ext_resource type="Script" path="res://entities/ball.gd" id="1_script"]

[sub_resource type="ParticleProcessMaterial" id="ParticleProcessMaterial_trail"]
# Keep the existing material properties here.

[sub_resource type="CircleShape2D" id="CircleShape2D_ball"]
radius = ...

[node name="Ball" type="CharacterBody2D"]
script = ExtResource("1_script")

[node name="Trail" type="GPUParticles2D" parent="."]
process_material = SubResource("ParticleProcessMaterial_trail")

[node name="CollisionShape2D" type="CollisionShape2D" parent="."]
shape = SubResource("CircleShape2D_ball")
```

Do **not** alter the material ID or the `process_material = SubResource(...)` reference—only relocate the existing block. The repository’s own architecture notes call out this exact defect: the late trail-material declaration in `ball.tscn` blocks all scene preloads and causes the cascade that appears as a `main.tscn` parser error.[1]

## Harden scene switching

Also update `autoload/screentransition.gd` so a failed destination load is explicit and cannot leave the transition state inconsistent. Replace `change_scene` with:

```gdscript
func change_scene(path: String, fade_duration: float = 0.3) -> void:
	if busy:
		return

	var packed: PackedScene = load(path) as PackedScene
	if packed == null:
		push_error("ScreenTransition: cannot load scene: %s" % path)
		force_reset()
		return

	busy = true
	guard_timer = 0.0

	await fade_out(fade_duration)

	var result: Error = get_tree().change_scene_to_packed(packed)
	if result != OK:
		push_error("ScreenTransition: failed to change to %s (error %s)" % [path, result])
		force_reset()
		return

	await get_tree().process_frame
	await fade_in(fade_duration)

	busy = false
	guard_timer = 0.0
	reset_overlay_state()
```

This does not “fix” a malformed scene, but it produces a direct error such as *cannot load scene: res://main.tscn* rather than silently returning to the launch UI. Your existing transition already owns a `busy` guard, timeout, overlay reset, and fade-tween cleanup, so this fits its intended contract.[1]

## Verify before running

After repairing `ball.tscn`, run a headless parse from the repository root:

```bash
/Applications/Godot.app/Contents/MacOS/Godot --headless --path . --editor --quit
```

Do not retry from the title screen until that exits cleanly with no `Parse Error`, `Failed loading resource`, or preload errors. The project’s contributor workflow explicitly requires this validation after every GDScript or scene-resource change.[1]

Then run `main.tscn` directly once. If it opens, Start from `ui/title_screen.tscn` should transition normally because `main.gd`’s explicit `PackedScene` preload will now successfully resolve `res://entities/ball.tscn`.[1]
