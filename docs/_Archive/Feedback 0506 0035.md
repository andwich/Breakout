## Launch / scene issues

**1. No wall collision bodies — critical**

This is the most significant structural bug. `ball.tscn` has `collision_mask = 5` (paddle + bricks), but `main.tscn` has no `StaticBody2D` walls for the left, right, or top edges. `move_and_collide` will never detect them, so balls silently fly off screen. `_on_screen_exited` only emits `life_lost` when `global_position.y > viewport.size.y` — all top and side exits just `queue_free()` silently, eating balls without consequence. You need three invisible wall bodies or manual boundary clamping in `_physics_process`.

**2. Pause / unpause is permanently broken**

`_toggle_pause()` has this guard:
```gdscript
if phase == GameState.Phase.GAME_OVER \
or phase == GameState.Phase.VICTORY \
or phase == GameState.Phase.PAUSED:
    return
```
When you press Escape to pause, `phase` becomes `PAUSED`. Pressing Escape again hits that guard and returns immediately — you can never unpause. The `PAUSED` guard was added to block pause during level transitions (which also sets `phase = PAUSED`), but it inadvertently blocks unpausing altogether. The fix is to check `get_tree().paused` first and always allow toggling off:

```gdscript
func _toggle_pause() -> void:
    if get_tree().paused:
        get_tree().paused = false
        phase = GameState.Phase.READY if get_waiting_ball() != null else GameState.Phase.PLAYING
        hud.show_pause(false)
        return
    if phase == GameState.Phase.GAME_OVER or phase == GameState.Phase.VICTORY:
        return
    # Also block during level transition — use a dedicated flag instead of PAUSED phase
    get_tree().paused = true
    phase = GameState.Phase.PAUSED
    hud.show_pause(true)
```

**3. Paddle sprite won't resize correctly**

`paddle.gd` uses:
```gdscript
sprite.size.x = target_width
```
But the `Sprite` (a `ColorRect`) in `paddle.tscn` is laid out with offset-based anchors (`offset_left = -50`, `offset_right = 50`). In Godot 4, setting `.size` on an offset-based Control has no effect — the size is derived from the offsets. The actual expansion/reset needs:
```gdscript
sprite.offset_left = -target_width / 2.0
sprite.offset_right = target_width / 2.0
```
As written, big paddle expands the collision shape but the visual doesn't change — a confusing experience.

**4. `complete_level()` and `_toggle_pause()` share the `PAUSED` phase**

During the 1.8-second level transition, `phase = GameState.Phase.PAUSED` (but `get_tree().paused` is NOT set to true, so game logic still runs). This conflates "level transition" with "player paused." Recommend adding a `_transitioning: bool` flag to `main.gd` and using it to guard input rather than co-opting PAUSED.

## Play mechanism issues

**5. `_clamp_min_speed()` Y-clamping is immediately diluted**

After a brick/wall bounce:
```gdscript
velocity = velocity.bounce(normal)
_clamp_min_speed()                      # adjusts Y to at least 50px
velocity = velocity.normalized() * speed  # ← re-normalizes, undoes the Y floor
```
Trace it: if bounce gives `(400, 10)`, `_clamp_min_speed` sets `velocity = (399.7, 50)`, then `velocity.normalized() * speed` = `(0.992, 0.124) * 350` = `(347, 43.4)`. The Y component ends up below 50 again. Fix: apply the component floor *after* rescaling, or reorder so the normalize comes first:

```gdscript
velocity = velocity.bounce(normal)
velocity = velocity.normalized() * speed
# Now enforce minimum angle
if absf(velocity.y) < 50.0:
    velocity.y = 50.0 if velocity.y >= 0.0 else -50.0
    velocity = velocity.normalized() * speed
```

**6. `signf(0.0)` returns 0 — ball can lock horizontal**

In `_clamp_min_speed()`:
```gdscript
velocity.y = signf(velocity.y) * 50.0
```
If `velocity.y` is exactly `0.0` (rare but possible on a perfectly angled paddle hit), `signf(0.0) = 0.0` in Godot 4, so `velocity.y` stays at zero and the ball never angles upward. Change to:
```gdscript
velocity.y = (50.0 if velocity.y >= 0.0 else -50.0)
```

**7. Multiball spawns 1 clone per ball, readme says 2**

The readme states "Spawns 2 clones per ball" but the code iterates `active` balls once, spawning one clone per original:
```gdscript
for original in active:
    if slots <= 0:
        break
    var clone := spawn_ball(original.position)
    ...
    slots -= 1
```
With one ball you get one clone (two total), not three. Either update the readme or add a second inner loop iteration:
```gdscript
for original in active:
    for _i in range(2):  # 2 clones per ball
        if slots <= 0: break
        ...
        slots -= 1
```

**8. `laser_manager.gd` uses `get_parent()` for scoring**

Per `agents.md`'s own conventions, groups and `get_parent()` are anti-patterns for core gameplay. The laser calls `main._on_brick_hit()` via `get_parent()`, which tightly couples `LaserManager` to being a direct child of `Main`. Emit a signal instead:

```gdscript
signal brick_scored(points: int)

# In _fire_laser():
brick_scored.emit(5)
if body.is_queued_for_deletion():
    brick_scored.emit(body.point_value)
```
Then connect in `main.gd`: `laser_manager.brick_scored.connect(_on_brick_hit)`.

**9. `_on_brick_destroyed` connects a `Callable` string form**

In `spawn_bricks()`:
```gdscript
Callable(self, "_on_brick_destroyed")
```
In Godot 4, the idiomatic form is `_on_brick_destroyed` directly as a `Callable`. The string form works but defeats static analysis and type checking. Same pattern in `complete_level`'s `create_timer().timeout.connect(...)` — those are fine, but `Callable(self, "method")` shouldn't be used.

**10. `show_level_complete()` API uses `false` as a sentinel**

```gdscript
func show_level_complete(level_or_false) -> void:
    if level_or_false == false:
```
This is untyped and relies on the caller passing `false` as a special "hide" signal. Better to split it:
```gdscript
func show_level_complete(show: bool, level: int = 0) -> void:
```
Or use a nullable: `func show_level_complete(level: int = -1)`.

## Aesthetic issues

**11. Brick glow shader is still edge-bright, not center-bright**

The retro notes this as fixed ("Inverted glow formula: center brightens"), but the current shader code still glows at edges:
```glsl
float edge = min(min(UV.x, 1.0 - UV.x), min(UV.y, 1.0 - UV.y));
float glow = 1.0 - smoothstep(0.0, 0.4, edge);  // 1.0 at edge, 0 at center
```
`edge` is 0 at the boundary and ~0.5 at center. `1.0 - smoothstep(0, 0.4, 0) = 1.0` → bright at edges. For center-glow:
```glsl
float glow = smoothstep(0.0, 0.4, edge);  // 0 at edge, 1 toward center
```

**12. Ball is a yellow square**

The ball is a `ColorRect` — a literal square. At 8px radius for the `CircleShape2D` but 16×16px rendered square, it looks obviously wrong on curves and glancing hits. A minimal fix: use `_draw()` in `ball.gd` to draw a circle:
```gdscript
func _draw() -> void:
    draw_circle(Vector2.ZERO, 8.0, Color(1.0, 1.0, 0.6))
```
And remove the `ColorRect` child from the scene. A circle also gives much better visual feedback for angle-of-incidence on paddle hits.

**13. No screen edge markers or playfield boundary**

Without walls (issue #1) there's no visual cue of where the play area ends. Even with walls added, having a faint neon border rect would significantly improve readability. Something like a 1px `NEON_CYAN` outline rect in `BackgroundOverlay` drawn via a shader or a separate `ColorRect` with `draw_rect` outlines.

**14. Power-up timer progress bar has no label**

When a power-up activates, only the progress bar appears. Players can't tell which power-up is active or what effect is expiring. A simple `Label` next to the `ProgressBar` updated with the power-up name would help substantially.

**15. `victory.gd` hardcodes level 6**

```gdscript
RunState.start_level = 6
```
This should derive from the definition: `LevelDefs.base_levels().size() + 1`. If you ever add a 6th base level, this silently skips it.

**16. `HUD` high score label starts hidden with empty text**

In `_ready()`:
```gdscript
high_score_label.visible = false
```
But in `hud.tscn` the label has `text = ""`. On first launch with no saved score, calling `update_high_score(0)` skips the show (correct), but if the label's initial layout is calculated before it's hidden, it may cause a brief layout flash. Minor, but worth initializing `text = " "` (single space) to pre-reserve layout space.
